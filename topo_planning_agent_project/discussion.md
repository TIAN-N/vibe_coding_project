## 一、对话时间线

### 2026-08-03 · 01 · 初始产品需求

用户提出设计智能拓扑看网规划助手平台，核心诉求包括：

1. Web 工作台需要包含历史会话、工作目录、可视化界面和大模型对话区域。
2. 用户上传 CSV、XLSX 等规划数据后，通过自然语言触发子网划分、环链识别、拓扑优化和新增站点规划。
3. 后端 Agent 根据意图匹配 `SKILL.md`，按技能说明调用相应 Python 原子算子。
4. 算子输出的设备和链路数据需要自动转换为 GIS 与逻辑拓扑。
5. 用户可以使用自然语言控制拓扑视图，例如展示以指定网元为根的环。
6. 后续原子能力需要能够复用当前任务结果，并在缺少数据或参数时与用户交互确认。
7. 先完成产品架构和高保真 HTML 原型，确认后再进入正式开发。

### 2026-08-03 · 02 · 产品边界确认

用户确认：

- 产品形态为 Web 应用。
- 算子暂时通过各 SKILL 对应的 Python 启动脚本执行。
- 会话、文件和结果保存在本地服务器文件系统。
- 首版只考虑单用户，不考虑多人协作。
- 首版同时保留 GIS 拓扑和逻辑拓扑。
- GIS 根据节点经纬度和链路呈现。
- 逻辑拓扑复用 `D:\vibe_coding_project\logic_topo_visual.py` 的布局算法和坐标输出。

### 2026-08-03 · 07 · 筛选与样式真实联动

用户指出数据过滤和样式规则虽然能够打开，但没有真实改变画面。

问题原因确认：

- 旧样式弹窗只显示提示，没有把设置回写到 Leaflet 和逻辑 SVG。
- GIS 链路没有纳入统一图层状态。
- 节点与链路缺少可用于筛选的数据属性。
- 过滤没有同步更新标签、链路、逻辑拓扑和统计指标。

用户确认后，原型完成以下升级：

- 数据筛选改为可视化控制抽屉。
- 支持名称、角色、子网、环链类型、风险等级和根节点。
- 支持多条规则、AND/OR、单条删除、重置和应用。
- 筛选同步影响 GIS 节点与链路、逻辑拓扑、标签和统计。
- 样式支持节点尺寸、节点着色、标签显隐、链路宽度、链路颜色、结果高亮色、底图亮度和弱化透明度。
- 所有设置使用统一可视化状态并实时预览。

### 2026-08-03 · 08 · 技术架构、接口与开发拆解

用户确认高保真基本满足要求，要求进一步完成：

- 技术架构方案。
- 模块化接口设计。
- 开发任务拆解。
- 解释 Agent 对话机制与大模型接入方式。

形成的核心方案：

- 浏览器不直接调用大模型，由后端 Agent 编排服务负责会话和工具执行。
- 大模型负责意图理解、任务规划、参数抽取和结果解释。
- Python 算子负责确定性拓扑计算。
- Agent 使用“显式状态机 + 结构化模型输出 + 白名单工具”的受控模式。
- 后端建议采用 FastAPI，元数据使用本地 SQLite，产物使用本地文件系统。
- 对话增量、确认、任务进度和可视化更新通过 SSE 推送。
- 四个原子能力实现统一 `SkillAdapter`。
- 视图控制指令生成结构化 `VisualCommand`，不重新运行算子。
- GIS 和逻辑拓扑共享统一 `topology.json` 和 `VisualState`。

发现的问题：顶层 `SKILL.md` 记录的 `atomic_capability_library/...` 子技能路径，与当前实际的 `subnet_division/`、`ring_chain_identify/`、`topo_rehoming/`、`new_site_plan/` 目录不一致。正式开发必须由技能注册表维护逻辑技能 ID、真实路径、入口脚本和版本。

### 2026-08-03 · 09 · Agent 框架与产品启动方式

用户询问 Agent 框架和产品启动方式。

Agent 框架建议：

- 首版采用 FastAPI、Pydantic、asyncio 自建轻量 AgentRuntime。
- 核心模块包括 TurnOrchestrator、ConversationContext、ModelGateway、IntentRouter、SkillRegistry、ToolRegistry、StateMachine、TaskCoordinator、Guard 和 EventPublisher。
- 不建议首版采用无限自主循环的通用 Agent。
- LangGraph 可作为候选，但需公司第三方软件评审，且不能替代技能、工具安全和任务持久化模块。

产品启动建议：

- 本地 Windows 用户会话中运行。
- 开发环境分别启动 FastAPI 和前端开发服务器。
- 正式环境将前端构建产物交由 FastAPI 托管，只保留一个本地端口。
- 使用桌面 Launcher 或托盘程序完成环境检查、服务启动、健康检查和浏览器打开。
- 默认访问地址建议为 `http://127.0.0.1:8765`。
- 首版不建议 Docker，因为需要本地 Python 算子、Windows 文件系统和默认应用打开。
- 不建议直接运行成 Windows Service，因为服务会话可能无法在用户桌面打开 Excel 或 WPS。

## 二、当前确认的产品需求基线

### 2.1 产品形态

- 产品名称固定为“智能规划助手”，品牌图标使用 `CoNET` 英文艺术字体。
- 单用户本地 Web 应用。
- 本地 Windows 后端与浏览器运行在同一台 PC。
- 浏览器负责交互和可视化，后端负责文件、会话、Agent、模型和算子。
- 本地文件系统保存上传文件、过程文件、任务输出和报告。
- 首次启动必须由用户初始化项目名称。
- 不同项目独立维护历史会话；不同会话独立维护工作空间、任务、对话和可视化状态。

### 2.2 核心用户旅程

1. 用户创建或切换会话。
2. 在工作空间连续上传规划数据。
3. 用户通过自然语言描述规划目标。
4. Agent 匹配 SKILL，检查输入和前序结果。
5. Agent 向用户确认缺失信息和关键参数。
6. 后端启动对应 Python 算子。
7. 平台轮询 `status.json` 并推送进度。
8. 算子完成后识别输出文件，生成报告和统一拓扑数据。
9. GIS 与逻辑拓扑自动刷新。
10. 用户继续通过自然语言控制视图或启动后续规划能力。

### 2.3 四个原子能力

| 技能 ID | 能力 | 当前目录 | 主要依赖 |
|---|---|---|---|
| `subnet_division` | 子网划分 | `subnet_division/` | 原始设备和链路 |
| `ring_chain_identify` | 环链识别 | `ring_chain_identify/` | 原始设备和链路 |
| `topo_rehoming` | 拓扑优化 | `topo_rehoming/` | 子网划分与环链识别结果 |
| `new_site_plan` | 新增接入站点规划 | `new_site_plan/` | 设备、链路和路网距离；内部涉及子网划分 |
